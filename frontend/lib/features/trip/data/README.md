# features/trip/data

API client and DTOs for trips (generated by the assignment pipeline) and
their ordered pickup stops, including the driver's execution actions
(start/complete/resolve stop).

## Contents

- `trip_api.dart` (`TripApi`)
  - `get(tripId)` — `GET /trips/{id}`.
  - `listMine()` — `GET /users/me/trips`: trips where the current user is
    driver or a stop participant.
  - `start(tripId)` — `POST /trips/{id}/start`: driver kicks off the trip;
    backend transitions to `IN_PROGRESS` with the first stop `ACTIVE`.
  - `complete(tripId)` — `POST /trips/{id}/complete`.
  - `updateStop(tripId, stopId, UpdateTripStopRequest)` — `PATCH
    /trips/{id}/stops/{stopId}`: driver resolves the current active stop.
  - Providers: `tripApiProvider`, `tripDetailProvider` (family by id),
    `myTripsProvider` — all `FutureProvider.autoDispose`.
- `trip_dtos.dart` (read model)
  - `TripStatus` (`assigned`, `started`, `inProgress`,
    `waitingForNextStop`, `allPassengersPicked`, `headingToDestination`,
    `completed`, `interrupted`, `unknown`) and `StopStatus` (`pending`,
    `active`, `navigating`, `arrived`, `pickedUp`, `cancelled`, `skipped`,
    `unknown`) — mirror the backend's `TripStatus`/`StopStatus` enums.
  - `NavigationTargetType` (`none`, `currentStop`, `finalDestination`) —
    drives which address `TripResponse.navigationAddress(...)` returns,
    populated by the backend's `TripNavigationResolver`.
  - `TripVehicleSummary`, `TripStopSummary` (per-stop address/lat/lng/status/
    ETA, `userId` null for Contact-backed passengers), `TripResponse`
    (driver info — `driverId` for legacy user-backed drivers,
    `driverParticipantId` for Contact-backed ones — vehicle, stops,
    `navigationUrl`/`navigationLabel` for the deep-link button, and
    `hasNavigation`).
- `trip_execution_dtos.dart` — `StopAction` (`pickUp`, `skip`, `cancel`) and
  `UpdateTripStopRequest`, kept separate from the read model since these are
  driver write actions only (Phase 3B).

## How it connects

Talks to the backend's `trip`/`tripstop` packages, downstream of
`AutoAssignmentService`/`AssignmentService` (`features/assignment/data`).
`navigationUrl` comes from the backend's `TripNavigationResolver` +
`GoogleMapsNavigationUrlBuilder` and is opened via `core/launch`. Consumed by
`features/trip/presentation` (all trip screens),
`features/driver/presentation`, and `features/passenger/presentation`
(thin mode wrappers around `TripDetailScreen`), plus
`features/assignment/presentation` and
`features/event/presentation/event_detail_screen.dart` for trip summaries.
